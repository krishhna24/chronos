Wait for it to become ready:

  kubectl -n {{ $ns }} rollout status statefulset/{{ $full }}

Check the API through the kube-apiserver service proxy:

  kubectl get --raw /api/v1/namespaces/{{ $ns }}/services/{{ $full }}:http/proxy/api/v1/resources
{{- if or (ne $ns "chronos") (ne $full "chronos") }}

This release is not the default chronos/chronos; point kubectl-at at it:

  export CHRONOS_NAMESPACE={{ $ns }} CHRONOS_SERVICE={{ $full }}
  # or per command: kubectl at --chronos-namespace {{ $ns }} --chronos-service {{ $full }} ...
{{- end }}

Open the dashboard:

  kubectl -n {{ $ns }} port-forward svc/{{ $full }} 8080:{{ .Values.service.port }}
  # then browse http://localhost:8080/

  # or, through kubectl proxy (the trailing slash is required):
  kubectl proxy
  # http://localhost:8001/api/v1/namespaces/{{ $ns }}/services/{{ $full }}:http/proxy/
{{- if .Values.readerRole.create }}

Grant users access. Role {{ $ns }}/{{ $full }}-reader allows `get` on
services/proxy for this Service only. NOTE: anyone bound to it can read the
recorded history of EVERY namespace, including deleted objects.

  kubectl apply -f - <<YAML
  apiVersion: rbac.authorization.k8s.io/v1
  kind: RoleBinding
  metadata:
    name: {{ $full }}-readers
    namespace: {{ $ns }}
  roleRef:
    apiGroup: rbac.authorization.k8s.io
    kind: Role
    name: {{ $full }}-reader
  subjects:
    - apiGroup: rbac.authorization.k8s.io
      kind: Group
      name: sre            # or kind: User, name: jane@example.com
  YAML
{{- end }}
